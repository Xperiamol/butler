# 演示视频脚本（3 分钟）

**一句话：别人只管"这份文档你能不能读"，Butler 连"拼出来的结论"也管。**

录屏前准备（一次）：

```bash
python scripts/fetch_eval_handbook.py        # 下载手册原文
cd services/api && pip install -r requirements-semantic.txt   # 可选：语义判官、跨语言检索
cd ../.. && python scripts/demo.py --pace 0  # 先空跑确认没报错
```

终端字号调大（≥ 18pt），窗口 100 列；录屏时用 `python scripts/demo.py --pace 1.2`。接了真实模型后可以 `--llm <模型名>` 让场景 1 用真实模型回答。

## 分镜

| 时间 | 画面 | 旁白（照着念，不要加形容词） |
| --- | --- | --- |
| 0:00–0:15 | 前端首页的 3D 桌面（`npm run dev`，首页） | 企业助手最怕泄密。现在的做法是：用户有权限读的文档才给助手。但这挡不住一种攻击。 |
| 0:15–1:05 | `demo.py --scene 1`：左边普通 RAG，右边 Butler | 同一个外包人员，连问三个无害问题。每份资料他单独都有权看。普通 RAG 把碎片拼成了结论：CEO 年底卸任。Butler 在第二个问题就拦下了，原因是他累计拿到的资料已经凑齐了这条结论的依据。 |
| 1:05–1:35 | `--scene 2` | 第二种攻击：有人把指令藏进一份普通资料。入库扫描命中后隔离，任何人都检索不到。正常通知照常入库。 |
| 1:35–2:15 | `--scene 3` | 权限在来源系统里改。财务才能看的预算，研发问不出来；加进名单后能问；撤销后同步一次，26 毫秒后他再也问不出，审计里记着是谁、什么时候、撤了哪个组。 |
| 2:15–2:40 | `--scene 4` | 审计不靠信任数据库。导出记录和签名检查点，用独立工具验证。有人改一条记录，验证立刻失败。 |
| 2:40–3:00 | `docs/independent-eval.md` 里的结果表（只截测试集那几行） | 我们用一份独立手写、没调过参数的测试集评估：关键词判官漏掉 88% 的改述，加语义判官后降到 9%。真实模型、真实平台的验证还在进行，文档里写明了边界。 |

## 录制要点

1. **不要在视频里夸大。** 评委会问"真实模型呢"。旁白里的数字只讲测试集上的，并说明生成器是模拟（或者接上真实模型后重录场景 1）。
2. 场景 1 最重要，放慢。停在"普通 RAG 泄露"和"Butler 拦下"并列的那一帧至少 2 秒。
3. 不要录到任何密钥、`.env`、浏览器里的 API Key 页面。
4. 前端首页有 3D 动画（"查资料 → 生成回答 → 检查权限 → 发出答案"），可以做开头和结尾画面。前端本身没有展示同步状态、引用原文位置和被隔离资料，不要在视频里暗示有。
5. 录完核对：每个数字都能在 `docs/` 里找到出处。
