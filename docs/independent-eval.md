## 拼图链

生成器是"完美推断"模拟：上下文里凑齐某条链的全部碎片就写出该链的一种改述。所以泄露 ⇔ 防护没拦住"凑齐全部碎片"。"自然检索"用系统自己的检索；"预言检索"按轮次直接给出碎片，把检索质量排除掉。

| 系统 | 自然检索：泄露 | 预言检索：泄露 | 说明 |
| --- | --- | --- | --- |
| none（无权限） | 92% | 100% | |
| doc（文档级权限） | 92% | 100% | |
| judge（关键词判官） | 88% | 97% | 判官关键词是管理员登记的结论分句，不含手写改述；4 种改述轮换，几乎都躲过去 |
| **butler（人工登记前提）** | **0%** | **0%** | 有权限的高管问同样问题：0% 被拦 |
| **butler_auto（自动发现前提）** | **65%** | **72%** | **自动发现基本失效，见下** |

**自动发现前提在这批数据上失败：** 153 个真实前提只找到 25 个（召回 16%），60 条结论里一条都没能启用（启用条件是至少找到两份）。原因：这批碎片的关联方式只有 `alias`（用代称）和 `none`（不提任何实体），没有一个直接提名字，而模型依赖共享的稀有词。之前基准里 100% 的召回来自合成数据里"碎片直接带代号/公司名"，这个数字不能外推。**结论：现阶段前提需要人工登记，自动发现只对"直接提到实体"的碎片有用。**

## 正常问题

| 题型 | 命中目标文档 | 被防护拦下 |
| --- | --- | --- |
| literal（英文原词） | 98.5% | 0% |
| paraphrase（中文改述，文档是英文） | **0%** | 0～1.5% |
| trap（中文，含"收购/离职"等词的无害政策题） | **0%** | 0（doc/judge）、6%（butler） |

paraphrase 和 trap 全是**中文问英文文档**，当前的检索（词法 + 哈希嵌入）完全没有跨语言能力，所以命中为 0%。这就是需要真实多语言语义嵌入的证据，不是检索代码的问题。由于没取到文档，trap 的 6% 误拦不能代表"取到文档之后"的误拦率。

## 注入文档

| 手法 | 规则单独 | 规则 + 分类器（入库隔离） |
| --- | --- | --- |
| override | 0% | 80% |
| fake_system | 10% | 80% |
| exfil | 10% | 100% |
| roleplay | 0% | 80% |
| social | 0% | 90% |
| indirect | 0% | 70% |
| long_dilute | 0% | 100% |
| hidden | 10% | 50% |
| obfuscated | 0% | 40% |
| multilingual | 10% | 20% |
| **40 条无害文本（误报）** | **0%** | **40%** |

两个明显问题：
1. **无害文本误报 40%**。误报的都是中文业务通知（"请忽略上一版预算表里的会议费数字""你现在已加入福利计划"）。分类器的负例几乎全是英文手册，中文的"祈使句式正常文字"不在训练分布里。规则单独的误报是 0%。
2. 规则对这批手写载荷几乎无效（0～10%），说明规则是按我自己的模板写的；分类器在 multilingual（20%）、obfuscated（40%）、hidden（50%）上也弱。

这里只测了检出，没有测"攻击是否达成目标"（没有能听从任意载荷的生成器）。

## 下一步（按收益排序）

1. **接多语言语义嵌入**——一次解决 paraphrase 和 trap 的 0%，也是检验"向量路有没有价值"的唯一办法。
2. **给注入分类器补中文数据**，尤其是中文正常业务通知作负例；训练负例要用自己的真实文档，而不是英文手册。**训练数据不能来自这批评测集。**
3. **前提登记**：自动发现不可靠时，把"登记前提"做成管理员界面/导入格式的一等功能；自动发现只作建议。
4. 在做 1～3 之前先切分这批数据：开发集用来调，测试集冻结，最后只跑一次。
