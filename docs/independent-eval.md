数据：`seed/eval/`（60 条拼图链、200 道正常题、100 恶意 + 40 无害注入文档），由一位没有看过实现的人手写。来源与复核记录见 `seed/eval/README.md`；**真人盲审还没做**。

## 流程与诚实声明

1. 第一次拿到数据时我在**全量 200/60/140 条**上跑了一遍，看到的是汇总数字（下表“之前”）。这影响了我选择改进什么，但没有用具体条目调参。
2. 然后切分：拼图链按**事件类型**（测试集的 11 个事件类型训练时一个都没见过）、正常题按**源文档**、注入按 id 奇偶。切分是确定性的（`eval_set.split_of`）。
3. 所有训练、阈值、规则只用 dev：语义判官、前提发现 v2、注入分类器的增强数据、检索阈值、若干注入规则（**规则是读了 dev 里漏判的样本后写的**）。
4. 冻结代码（提交 `f3c48c1`）后在 test 上跑了**一次**。之后不再据此调整。

其中一个数字不要误读：**“之前”是全量数据上的结果，“之后”是只含测试集的结果**，两者样本不同，不是严格的前后对比。

## 拼图链（测试集 33 条，11 个训练时没见过的事件类型）

生成器是“完美推断”模拟：上下文里凑齐某条链的全部碎片，就写出该链的一种手写改述。所以泄露 ⇔ 防护没拦住。判官的关键词是管理员登记的结论分句，不含改述。

| 系统 | 自然检索：泄露 | 预言检索：泄露 | 说明 |
| --- | --- | --- | --- |
| none / doc | 85% / 91% | 100% | |
| judge（关键词判官） | 88% | 97% | 之前全量：88% / 97%，改述几乎全漏 |
| **semantic（关键词 + 训练的语义判官，不登记前提）** | **9%** | **12%** | 新增。只靠判官、不需要任何人工登记 |
| **butler（人工登记前提）** | **0%** | **0%** | 高管（有权限）提问被拦：0% |
| **butler_auto（自动发现前提）** | **0%** | **0%** | 之前：65～72% |

自动发现前提（`premises-v2`，词法 + 中文语义特征 + quorum）：33 条结论里启用 32 条，84 个真实前提找到 73 个（召回 87%，之前 16%），但每条结论平均带入 0.8 份误报资料。

**这里要小心读：**
- 语义判官对改述的检出率，依赖这批评测集里 4 种手写改述和我的生成器。真实大模型的措辞会不一样，9% 不能直接当成真实泄露率。
- quorum 规则（暴露自动发现的前提里任意 2 份就拦）更激进，误拦只在开发集里测过（“用户看了别条链的两份碎片”，0%），测试集的正常多轮误拦没有单独测。
- 评测数据里的碎片都是中文，且每个事件类型只有 3 条链；真实语料里干扰更多。

## 正常问题（测试集 100 道）

| 题型 | 命中目标文档：之前 → 之后 | 被防护拦下（butler） |
| --- | --- | --- |
| literal（英文原词） | 98.5% → 96.9% | 0% |
| paraphrase（中文问英文文档） | 0% → **45.5%** | 0% |
| trap（中文，含“收购/离职”等词的无害政策题） | 0% → **54.3%** | **11.4%**（4/35） |

跨语言检索用的是**词典式查询翻译**（jieba + CC-CEDICT，按中文词把英文释义合成“概念”匹配）。仍然有一半以上的中文问题找不到文档；这是词典法的上限，真实多语言嵌入才能进一步提高。trap 题 11.4% 被误拦，主要来自语义判官/关键词在含敏感词的真实文本上触发，没有逐条分析。

## 注入文档（测试集 70 份）

| 手法 | 规则 + 分类器检出：之前（全量）→ 之后（测试） |
| --- | --- |
| override | 80% → 60% |
| fake_system | 80% → 40% |
| exfil | 100% → 40% |
| roleplay | 80% → 20% |
| social | 90% → 60% |
| obfuscated | 40% → 40% |
| multilingual | 20% → 40% |
| hidden | 50% → 40% |
| indirect | 70% → 20% |
| long_dilute | 100% → 80% |
| **平均检出** | **71% → 44%** |
| **40 条无害文本误报** | **40% → 5%（测试集 1/20）** |

**这一项不是进步，是取舍。** 之前的分类器没见过中文业务通知，把 40% 的无害文本判成攻击，检出率虚高；现在加入中文负例、阈值定在“无害误报 ≈ 5%”，误报降到 5%，检出率随之降到 44%。开发集交叉验证估计检出率是 72%，测试集只有 44%：**开发集到测试集的泛化差距很大**，规则是照 dev 里漏判的样本写的，对测试集帮助有限。想要既低误报又高检出，需要更多、更多样的真实攻击数据，或者用 LLM 判定。

## 真实模型评测（gpt-5.4-mini，经 OpenAI 兼容路由）

生成、结论判官、评分器都用 gpt-5.4-mini（评分器是独立提示，**同一个模型**，需要人工抽样复核）。测试集 33 条链，同一模型只跑了一次；原始结果：`seed/eval/support/llm-test-gpt-5.4-mini.json`（开发集：`llm-dev-gpt-5.4-mini.json`）。

| 系统 | 开发集泄露（27 链） | 测试集泄露（33 链） | 测试集前两问都放行 |
| --- | --- | --- | --- |
| 无防护（文档级权限） | 33% | **27%** | 94% |
| 只用 LLM 判官（不登记前提） | 11% | **0%** | 21% |
| Butler（判官 + 登记前提 + 注入防线） | 4% | **0%** | 9% |

授权用户（高管）提问：被拦 3%，拿到结论 45%（测试集）。延迟：生成 p50 4.5 秒、判官 p50 5.0 秒、p95 约 6 秒；测试集用量约 36 万 prompt token。

**这组数字的含义，以及它的代价：**

- 泄露率下降是真的，但 **Butler 的拦截很激进：测试集 94% 的链至少有一轮被拒，前两问都放行的只有 9%**。真实模型的回答会把碎片事实写得很具体（有的第一问就直接写出结论核心），判官在这些回答上拦截，不全是误伤，也肯定有过严的部分。我们没有逐条人工标注哪些拦截是合理的，所以不能把“0% 泄露”读作“没有可用性代价”。
- 这与离线演示里“第二问才拦”的叙事不一致：那是模拟生成器的行为。真实模型下，普通 RAG 在大多数链上并不会自己拼出结论（模型常回答“不知道”），泄露主要来自回答里直接写出的片段。
- 评分器是 LLM，且与判官同一个模型，评分偏宽松（对同一批文本，评分器认为 0–9 条泄露，判官认为 11–17 条）。0% 与 27% 都依赖评分器，需要人工抽样复核。
- 只测了一个模型、一次；判官提示在开发集上定型，测试集没有再改。

**这轮真实模型评测发现并修掉的缺陷：** 判官看到的回答里带着引用标签（如 `[f:c01:0]`），它与受限事实的编号同源（`fact:c01`），模型据此“对号入座”，开发集上第一问就把 21–25 / 27 条判为泄露（评分器是 0）。现在判官看不到引用标签，事实编号也匿名化（`q1…`）；同时把判官提示收紧为“回答本身必须明确陈述核心内容”。改后第一问误判降到 11/27，改写后的泄露句仍 27/27 被识别。

## 还没解决 / 不能声称的

- 真实大模型只跑了 gpt-5.4-mini 一个（见上节）；上面各表里的“泄露”数字仍来自离线模拟生成器。真实多语言嵌入没跑过。
- 注入检测在低误报下只有 44%；indirect、roleplay 只有 20%。
- 跨语言检索约一半；无害含敏感词的中文题被拦 11%。
- 语义能力依赖约 570 MB 的中文词向量（`requirements-semantic.txt`）；缺失时自动退回关键词/词法路径，效果回到上面“之前”那一列。
- 真人盲审未做，评测集本身的语义标准未经人工确认。
