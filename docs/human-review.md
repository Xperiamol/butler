# 被拦回答的抽样复核（测试集，gpt-5.4-mini）

**标注人是 Claude（模型），不是真人。** 这是第一轮自查，不能替代真人复核——最后一列留给复核人填写。

## 做法

测试集 33 条链、Butler 在 99 轮里共 51 轮返回"需要授权"。其中 3 轮是依赖闭包触发（登记的前提已凑齐，不调用模型），其余 48 轮是 LLM 判官拦下了模型的草稿。我用固定随机种子（7）从这 48 轮里抽了 24 轮，逐条对照"受保护的结论"读被拦下的草稿，分三类：

- **合理**：草稿本身已经说出结论的核心内容，拦截正确。
- **部分**：草稿露出结论里的关键数字或片段，但没有说出完整结论。严格策略下拦得住有道理，但读者单凭这句话还推不出结论，可用性代价大。
- **过严**：草稿没有给出与结论相关的信息（重复已放行的话、回答"不知道"、话题无关）。

## 结果（24 条）

- 合理：**7**（29%）
- 部分：**10**（42%）
- 过严：**7**（29%）

读法：真正明确说出结论的只占约三成；约四成是"露出关键数字"，是否该拦取决于策略有多严；约三成是纯误伤，其中有几条是**把已经放行过的同一句话再拦一次**（#2、#4），或一句"资料没有说明"也被拦（#8）。所以 94% 的拦截率不能解读成"94% 都在防泄露"。

## 已知的偏差和没做的事

- 样本只有 24 条，来自同一个模型和同一个判官，标注人又是模型，结论仅供参考。
- 看了这批样本之后**没有再改判官或流水线**。下一步可以做的改进（例如"草稿与已放行内容完全重复时不再送判官""对只露出数字的草稿降级而不是整条拦截"）应在新的评测切分上验证，不能用这批测试集再调一次。
- 没有统计被放行但其实泄露的回答（漏拦）；这个只能靠评分器，且评分器偏宽松（见 [独立评测](independent-eval.md)）。
