# 检索评测：切块 + 混合检索

## 做了什么

- **切块**（`ingest/chunking.py`）：按标题/段落/列表/表格切，目标约 450 token、重叠约 60 token（只在同一小节内重叠）；块文本是原文的精确子串，保存 `[start, end)`，引用能定位到原文位置；表格被切开时表头进元数据。
- **向量**（`ingest/embedding.py`）：统一 `Embedder` 接口。离线默认是**无需拟合的哈希 n-gram 嵌入**（不用在全库上拟合的 LSA，避免把受限文档的词频带进每个人的检索基底）；`RemoteEmbedder` 对接 OpenAI 兼容的 `/embeddings`（批量、429/5xx 退避、维度校验、错误不带响应体）。向量按 `(模型, 输入哈希)` 存储并复用，内容没变就不重算。
- **索引**（`ingest/index.py`）：读 → 向量化（不持锁）→ 原子换版本。块不保存权限，检索时与 `documents` 里的当前 ACL 关联，所以撤权/授权不需要重新向量化。向量服务故障时导入不失败，文档走“滞后文档现场切块 + 词法”兜底。
- **检索**（`retrieval/hybrid.py`）：先按权限过滤，再在可见块上做 BM25（含覆盖率闸门、拼写纠正、子句拆分）和精确余弦两路召回，RRF 融合；词频统计只来自可见文档。同一文档命中的多个块合并成带原文位置的段落集合。

## 评测（GitLab 手册 545 篇、2003 个块，100 篇 × 3 类查询）

```bash
cd services/api && python -m butler.retrieval.eval --handbook ../../.corpus/handbook --n 100 --seed 3
```

| 检索方式 | 标题类 recall@6 | 正文摘句 | 摘句+丢词+拼写错误 | 无关问题误召回 |
| --- | --- | --- | --- | --- |
| legacy（旧：整篇字符二元组） | 59% | 99% | 76% | 70% |
| 块 + BM25 | 99% | 100% | 99% | 0% |
| 块 + 哈希向量 | 81% | 85% | 27% | 0% |
| **混合** | **99%** | **100%** | **99%** | **0%** |

中文：30 个对照问题全部召回，4 个无关问题全部拒答（`tests/test_hybrid_retrieval.py`、工作区测试）。

## 必须说明的

- **混合的收益主要来自“块 + BM25 + 拼写纠正 + 校准过的拒答闸门”，不是向量。** 哈希嵌入没有语义，向量路单独远不如词法；混合没有比纯词法更好。向量路的价值要接真实语义嵌入后才体现，这里没有可下载的预训练模型（沙箱访问不了模型仓库），所以没有测。
- 查询是从文档自身取的句子，天然偏向词法匹配；没有人工撰写的同义改写问题集。
- 无关问题只有 20 条，闸门阈值（`MIN_COVERAGE`、`DENSE_MIN`）是在这批数据上校准的，换语料需要重新校准。
- 向量搜索是精确搜索（numpy），块数上万以后再评估 HNSW；ANN 过滤会影响返回数量，不能当作权限检索的替代。
