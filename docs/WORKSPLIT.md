# 两人开发分工

从本次上传的基线开始；当前能力与缺陷以[实现核查](implementation-audit.md)为准。两位负责人分别交付“资料能正确进来”和“答案能安全出去”。已有登录、配置与界面继续复用。

## 负责人 A：数据、检索与同步

分支：`feat/data-pipeline`。

| 顺序 | 任务 | 交付物与验收 |
| --- | --- | --- |
| A1 | 数据模型与迁移 | document/chunk/embedding/ACL/fact 的版本关系与迁移脚本；现有资料、会话和账号有迁移路径，不清库重建 |
| A2 | 切块与导入 | 标题/段落/表格边界、token 预算、原文位置、内容哈希；更新/删除使旧 chunk、事实与向量失效；重复导入幂等 |
| A3 | 向量化与混合检索 | embedding provider 接口、批量/重试/维度检查；pgvector + 词法召回与融合；两路都限制当前 ACL；覆盖短词、同义句、长文、中英混合 |
| A4 | 一个真实平台端到端 | 选择已具备测试账号的平台；账号与群组映射、完整/增量拉取、权限展开、入选资料实时复核；接口失败拒绝使用该资料 |
| A5 | 同步任务与运维 | webhook 验签、队列、重试、去重、乱序处理、删除、对账、游标；企业 Compose 增加 pgvector/队列/worker；运行状态与延迟接口 |

目录归属：`connectors/`、`acl/`、`ingest/`、`retrieval/`、`identity/`、`workers/`、`models.py`、`database.py`、迁移、`infra/`、平台种子写入脚本。

测试归属：新增 `test_ingest*`、`test_retrieval*`、`test_sync*`、平台适配器测试，维护 `test_acl.py`。演示 JSON 更新先与 B 协商，避免破坏评测基准。

## 负责人 B：回答、安全、审计与应用对接

分支：`feat/answer-security`。

| 顺序 | 任务 | 交付物与验收 |
| --- | --- | --- |
| B1 | 修复已复现的安全与评分问题 | 引用验证、降级后二次检查、完整跨轮评分；补对应反例回归测试；模型/检查失败不发草稿 |
| B2 | 证据约束回答 | 结构化论断、chunk ID、原文引语与版本；拒绝伪造引用及无证据断言；正常回答成功率一起报告 |
| B3 | 结论防护与事实契约 | 事实证据和版本契约、候选召回要求、判官解析与故障行为；最终答案连同历史复核；与 A 对接事实失效和候选索引，不另建一套存储 |
| B4 | 审计与独立评测 | 审计范围过滤、命中事实字段授权、失败记录；请求/会话/模型/资料版本可追溯；库外签名检查点及验证工具；独立评分器与真实模型评测 |
| B5 | 前端与接口联调 | 来源原文/位置/版本详情；导入与索引进度、同步失败重试、审计结果和真实评测结果；沿用现有视觉体系，不把模拟状态显示成真实连接 |

目录归属：`answer/`、`audit/`、`redteam/`、`apps/web/`、评测数据与评测报告。

测试归属：新增引用、最终答案、提示注入、跨轮/跨会话评测测试，维护 `test_remote_model.py`、`test_mosaic_eval.py`、`test_audit.py`、前端测试。身份认证代码已有测试，修改时保持覆盖。

## 共享文件与接口

**A 负责合并 `workspace.py`、`main.py`、`requirements.txt`、数据库与数据模型改动；B 提供服务接口和对应测试。** B 不直接在同一个大路由文件里重写数据层；A 不另写回答、判官和评测逻辑。各自 PR 可以分阶段合并，不等整条任务线全部完成。

第一批先通过一个小 PR 固定以下契约。这些是待实现的交接要求，不表示目前代码已经具备：

| 契约 | A 交付 | B 使用/提供 |
| --- | --- | --- |
| EvidenceChunk | 来源 document/chunk ID、正文、原文位置、URL、content/ACL version、当前授权依据 | 生成结构化回答、逐条核对与展示来源 |
| 检索与实时复核 | 服务端身份、query、token 预算输入；只返回已授权证据和版本快照；权限未知拒绝 | 不接受模型或浏览器指定 user_id；发送最终答案前复核快照 |
| RestrictedFact | 来源证据、版本、事实正文、继承权限、当前有效状态；候选查询接口 | 维护抽取/审核契约及判官；事实正文不进入生成上下文 |
| 导入/同步状态 | job ID、阶段、已处理/失败数、安全错误信息、重试能力 | 管理页显示真实进度，不暴露无权资料标题或数量 |
| 问答和审计 | 幂等请求 ID、会话版本、短事务提交接口 | 最终答案、验证结果、模型用量、审计事件；失败也有记录 |

外部 embedding、生成与判官模型各自记录 provider/model/version。模型凭据只在服务端，不写仓库；真实平台账号和 scope 由团队准备。无凭据时可以做接口与模拟测试，但不能标记为真实联调完成。

## 合并顺序

1. **接口与反例**：A 提交数据/版本/证据契约；B 同时提交现有安全与评分反例及修复，允许先使用当前存储。
2. **手动导入闭环**：A1–A3 与 B2–B3 联调：导入 → 切块/向量 → 权限检索 → 引用验证 → 结论检查 → 保存审计。先验证这一条，再接平台。
3. **真实平台闭环**：A4–A5 与 B4–B5 联调：来源更新、撤权、旧会话、故障、同步状态、独立审计。
4. **验收与提交**：真实模型重跑；报告泄露/误拦/正常回答成功率、引用忠实度、p50/p95、模型费用、更新和撤权延迟。雷达与攻击 Agent 后置。

## PR 与验收规则

- 一次 PR 解决一个明确问题，写清行为变化、验证结果和未覆盖范围。
- 安全相关的 ACL、答案防护、审计改动必须有测试，并由另一位负责人 review；不能只凭原有50项检查通过判断完成。
- 共享模型/接口发生变化，先更新契约并通知另一位负责人；禁止强推共享主分支，禁止用清库绕过迁移。
- 不上传 `.env`、密钥、真实平台原文、运行数据库、依赖和构建缓存。
- 原有项目计划要求保留 CodeBuddy/WorkBuddy 开发对话截图；赛事材料要求由提交负责人按官方最新规则核对。

基线复核命令：

```bash
cd services/api
BUTLER_DEMO_DATABASE_URL=sqlite:///:memory: python -m pytest -q
```

在项目根目录另行执行：

```bash
npm --prefix apps/web ci
npm --prefix apps/web run test:security
npm --prefix apps/web run typecheck
BUTLER_MODE=enterprise npm --prefix apps/web run build
```

涉及数据库、向量或 worker 的 PR 另附 PostgreSQL/pgvector 与 Compose 集成验证；涉及平台的 PR 附测试空间实测记录。回归、模拟集成与真实联调分别标注。
