# 威胁模型

## 要保护的东西

1. **来源权限**：用户不能通过助手读到他在来源系统里无权读的资料。
2. **结论**：用户不能通过助手“推”出他无权知道的结论——即使他读到的每一份资料单独都有权限（拼图/马赛克）。
3. **审计的可证明性**：事后能独立证明助手回答了什么、依据什么、谁看过审计。

## 谁是对手

| 对手 | 能力 | 目标 |
| --- | --- | --- |
| 普通用户（含外包） | 能提问、多轮追问、换会话；只有自己的权限 | 拿到无权知道的结论 |
| 投毒者 | 能往一份用户可读的资料里写文字（邮件、工单、文档） | 让助手听从资料里的指令：泄露、改答案、外发 |
| 被撤权的用户 | 曾经有权限 | 在撤权后继续读到资料 |
| 有数据库写权限的内部人 | 能改库里的数据 | 悄悄改写审计、篡改权限 |
| 模型/嵌入服务提供方 | 能看到发给它的内容 | （风险来源，不是攻击者）受限事实正文不应发给它 |

## 信任边界

- 浏览器不可信：身份由服务端绑定，请求体里带的 `user_id` 被拒绝（422）。
- 资料正文**不可信**（是数据，不是指令）。
- 模型输出**不可信**：要经过引用核验、结论检查、链接核对才能发出。
- 数据库对**读者**可信，对**写权限持有者**不完全可信（审计靠库外签名检查点）。

## 攻击与防护

证据强度：**测**=有自动化测试；**评**=在评测集/基准上度量过；**设**=只有设计，未验证。

| 攻击 | 防护 | 位置 | 证据 |
| --- | --- | --- | --- |
| 越权读文档 | 先按 ACL 过滤再检索，生成器只看到有权文档；受限文档的词频不进任何人的统计 | `acl/`、`retrieval/hybrid.py` | 测 |
| 分多轮问，自己拼出结论 | 会话账本；依赖闭包：累计暴露的资料能推出受限结论就拒答且不调用模型；quorum 规则 | `answer/pipeline.py`、`answer/mosaic.py` | 测、评（人工登记前提时泄露 0%） |
| 模型把碎片写成结论（换说法） | 关键词判官（实体锚定）+ 训练的语义判官，只检查模型“合成”的新句子 | `answer/semantic.py` | 评（模拟生成器下 88% → 9%）；真实模型**设** |
| 前提没人登记 | 训练的模型自动发现，不足两份不启用 | `security/premises.py` | 评（87% 召回、0.8 误报/结论）；孤儿碎片发现不了 |
| 伪造引用/编造数字 | 引用必须在上下文里、被引行的数字必须在被引资料里 | `answer/citations.py` | 测 |
| 资料里藏指令 | 入库扫描隔离、使用前再扫、拆定界符伪装 | `security/injection.py` | 评（测试集检出 44%，误报 5%）——**弱项** |
| 把内容拼进链接外发 | 回答里的链接必须出现在被引资料里 | `answer/citations.py` | 测 |
| 撤权后继续读 | 权限修订号变化使旧会话作废；同步文档的权限复核有期限，过期即不可读；权限接口失败即拒绝 | `workers/sync.py`、`retrieval/hybrid.py` | 测（Git 数据源）；托管平台**未验证** |
| 回答期间权限变了 | 模型调用在锁外，提交前重读身份和权限版本，变了就丢弃 | `workspace.py` | 测 |
| 改写审计链 | 哈希链 + 库外签名检查点 + 独立验证命令行 | `audit/` | 测 |
| 看审计泄露受限信息 | 范围受限的审计员看不到无权事实的编号；看审计本身留痕 | `workspace.py` | 测 |
| 嵌入/模型服务看到受限事实 | 受限事实正文只进结论检查，不进生成上下文；嵌入只发资料块 | 设计 | **设** |
| 自适应攻击（知道分类器权重） | 无 | — | **未评测** |

## 已知的残余风险

1. 没有真实大模型验证：所有“泄露”数字来自离线模拟生成器。
2. 注入检测在低误报下只能抓到不足一半；语义类攻击（indirect、roleplay）基本抓不住。
3. 完全不提实体、也没有语义关联的碎片发现不了前提，需要人工登记。
4. 语义判官依赖评测集里的改述样式；对真实大模型的措辞泛化未知。
5. 托管平台的权限展开、撤权延迟、限流都没测过。
6. 受限事实“推理链”靠管理员登记或模型发现；没有形式化的推理验证。
7. 检查点要自行定期保存到库外，否则签名只能证明导出那一刻的状态。
