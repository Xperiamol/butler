# 前提自动发现

依赖闭包防护需要知道"哪几份资料合在一起能推出某条受限结论"（`Fact.premises`）。人工登记不现实，这里训练一个小模型自动发现。

## 做法

- **候选**：只考虑"有人读得到、而这个人读不到该机密"的资料（ACL 不被来源文档的 ACL 包含）。同级别的其他机密不可能构成前提。
- **预筛**：按与机密共享的稀有词信息量取前 40 个候选。
- **打分**（`security/premises.py`）：逻辑回归，9 个特征——共享稀有词信息量占比、共享词数、最大 IDF、候选自身的指向性、TF-IDF 余弦、哈希嵌入余弦、与结论陈述的重叠、机密最稀有 3 个词出现的比例、最稀有词是否出现。刻意不含文档长度和预筛名次（第一版用了长度，学到的是"合成碎片都很短"这种数据伪影，已去掉）。
- **决定**：概率 ≥ 阈值的取前 4 个；**不足两份就不启用**（单份资料本身不构成"拼图"，否则会把无害的单份资料误拦）。人工登记的前提永远优先。
- **运行**：管理侧离线计算（用全库词频），在导入/同步后刷新，结果存在事实的 `auto_premises` 里，不暴露给提问者。权重 JSON：`security/models/premises-v1.json`。

## 训练与评估

```bash
cd services/api && python -m butler.security.train_premises --handbook ../../.corpus/handbook --write
```

- 训练：8 种事件类型（高管离任、涨价、停产、审计发现、诉讼和解、冻薪、关闭办公室、漏洞）× 3 种关联方式（A 提代号 B 提公司 / 都提公司 / 都提代号），真实手册文档当背景。
- 评估：**训练里没有的**三种事件类型（收购、裁员、泄露）；30 条链，其中 6 条是孤儿链。

| 指标（未见过的事件类型） | 结果 |
| --- | --- |
| 非孤儿链：两份前提都找到 | 100%（24/24 条） |
| 孤儿链的碎片 B | 0%（找不到，符合预期） |
| 每条结论平均误报资料数 | 0.03 |

放进完整基准（545 篇手册 + 24 份被投毒资料 + 30 条链）后：启用 24–27/30 条结论，真实前提找到 54/60（缺的就是 6 份孤儿碎片），误报资料 7–13 份（0.2–0.4 条/结论）。对应的端到端结果见 `benchmark.md` 的 butler_auto 一行：泄露 7–17%。

## 局限

- **只能发现与结论共享稀有词的资料。** 完全不提实体的碎片发现不了。
- 评估数据是合成的，每条链的代号和公司首词唯一，真实场景里项目名会反复出现、同名干扰更多，召回和误报都会比这里差。
- 训练过程里发现并修掉了两个数据伪影（碎片长度、不同链的名字共享首词）。说明这类模型对数据构造很敏感；换语料要重新评估，不能直接沿用阈值。
- 没有"前提间必须同时具备"的因果判断：模型只估计相关性，"合在一起才能推出"仍是一个近似。
