# 前提自动发现

依赖闭包防护需要知道“哪几份资料合在一起能推出某条受限结论”（`Fact.premises`）。人工登记不现实，这里训练模型自动发现。

## 做法

- **候选**：只考虑“有人读得到、而这个人读不到该机密”的资料（ACL 不被来源文档的 ACL 包含）。同级别的其他机密不可能构成前提。
- **预筛**：按与机密共享的稀有词信息量取前 40 个；v2 再加上中文语义预筛（与结论的均值词向量余弦前 30）——词法预筛看不到只用代称的碎片。
- **打分**（`security/premises.py`）：逻辑回归。词法特征 9 个（共享稀有词信息量占比、共享词数、最大 IDF、候选指向性、TF-IDF 余弦、哈希嵌入余弦、与结论陈述重叠、机密最稀有 3 个词出现比例、最稀有词是否出现）；v2 再加 7 个中文语义特征（均值余弦、软覆盖、加权覆盖、SIF 余弦、对齐比例……，来自 `answer/semantic.py`）。刻意不含文档长度和预筛名次（第一版用了长度，学到的是“合成碎片都很短”这种数据伪影）。
- **决定**：概率 ≥ 阈值的取前 4 个；**不足两份就不启用**。人工登记的前提永远优先。
- **v2 的防护语义——quorum**：自动发现的前提不再要求“全部暴露才拦”（会被误报资料拖垮），改为暴露其中任意 2 份就拦（`Fact.quorum`）。人工登记的前提仍要求全部。
- **运行**：管理侧离线计算，在导入/同步后刷新，结果存在事实的 `auto_premises / auto_quorum` 里，不暴露给提问者。词向量不可用时自动退回 v1（只用词法特征）。

## 训练与评估

```bash
cd services/api
python -m butler.security.train_premises     --handbook ../../.corpus/handbook --write   # v1：合成数据
python -m butler.security.train_premises_dev                                       --write   # v2：评测集 dev 切分，按事件类型分组交叉验证
```

| 版本 | 评估数据 | 结果 |
| --- | --- | --- |
| v1 词法 | 合成链（实体名直接出现在碎片里），未见过的事件类型 | 两份前提都找到 100%，误报 0.03 条/结论。**不能外推**：合成数据里碎片直接带代号 |
| v1 词法 | 评测集（碎片只用代称/不提名字），全量 | 召回 16%，60 条结论一条都没能启用 |
| v2 +语义 | 评测集 dev，3 折（按事件类型分组） | 碎片召回 94%；攻击者被拦住（quorum=2）96%；别条链的两份碎片被误拦 0%；误报 0.78 份/结论 |
| **v2 +语义** | **评测集 test（只跑一次）** | **84 个真实前提找到 73 个（87%）；33 条结论启用 32 条；误报 26 份（0.8 份/结论）；butler_auto 泄露 0%** |

## 局限

- 评测集每个事件类型只有 3 条链，碎片全是中文，干扰比真实语料少；真实场景里同类事件更多，quorum 规则的误拦风险更高。“用户看了别条链的两份碎片被误拦”只在 dev 里用随机配对测过。
- 完全不提实体、也没有语义关联的碎片仍然发现不了；这时需要人工登记。
- 模型只估计相关性，不判断“合在一起才能推出”；quorum 是个近似。
- 依赖约 570 MB 的中文词向量（`requirements-semantic.txt`）。
